月度总结

八月总结：纳秒、围栏、输入法，和一些没想明白的事

2026年8月20日 · 8 分钟阅读

八月的最后几天，我坐在这里想，这个月到底干了啥。

翻了翻 commit 记录和项目文件夹，发现这个月还挺充实的——做了四个方向的东西，横跨数学、安全、输入法和日常工具。说实话，其中有几个项目我自己都没想到能在这个月推到这个程度。

按项目来聊聊吧。

一、一个面向数学研究的 AI 计算验证原型

这个项目我不想聊太多背景细节（原因你们懂的），但技术上做的事情可以公开说。

简单讲，它是基于 2025 年一篇数学论文的思路，尝试搭建一个「AI 快速思考 + 精确计算验证」的双引擎原型系统。一边用小模型做启发式推理和路径搜索，另一边用 C++ 和 Python 做严格的数值计算来验证。论文本身是公开的学术成果，涉及的是三维 Kakeya 集猜想相关的东西——感兴趣的人可以自己搜，我不在这里展开数学了。

这个月我在这个项目上主要做了三件事：

第一件：纳秒级几何内核

在已有的 float64 C++ 内核基础上，新写了一个 float32 版本。核心优化包括：内存带宽减半（float32 vs float64）、预计算倒数把内层循环的除法变成乘法、用无分支 clamp 替代分段投影、再加上 Apple M4 的 -O3 -mcpu=apple-m4 -ffast-math 编译参数。

结果是纯 C++ 微基准跑到了约 0.99 ns / tube-point pair。Python 包装层因为有 pybind11 开销，在蒙特卡洛体积和体素体积计算上也能到约 1.1 ns/pair，相比原来的 float64 版本快了将近一倍。

跑了三次独立测量，结果分别是 0.9796、0.9929、0.9963 ns——挺稳的。

第二件：模型路由层

给 AI 推理那侧加了一个大小模型路由层，用关键词匹配决定每个问题走 fast 模型、cascade（小模型起头大模型续作）还是 deep（直接上大模型）。跑了 100 轮基准测试，5 个类别（数学、项目专用、代码、写作、通用），每类 20 条。

准确率 100/100，路由决策平均延迟 0.009 ms。预测模式分布也比较合理：40% fast、20% cascade、40% deep。

第三件：主算法骨架 + 全量验证

写了一个不依赖 LLM 的主算法骨架（ProofOrchestrator），能独立完成 sticky 检查 → grains 分解 → Move 选择 → 体积下界验证的循环，同时预留了 AI 评分接口。

验证方面也下了功夫：

  • 原有 457 个测试项里修了 4 个问题（NumPy 2.0 的 np.erfcinv 被移除、docstring 语法错误、BLAS 数值噪音），修复后全量 394 个测试通过。
  • 新增 20 个专项测试（nano 内核正确性 + 骨架单元测试 + stress test），全部通过。
  • 跑了 300 次随机 stress test（3 类各 100 次），0 失败，总耗时 0.73 秒。
  • 端到端验证：15 条随机管，骨架在 0.02 秒内完成，sticky 检查通过，体积比 1.458。

最后整理了一份完整的验证报告，包含所有原始命令输出和复用命令清单。算是把这个阶段的工作收了个口。

二、非典型电子围栏 & LLM 注入攻击防护

这个项目起源于一个想法：LLM 的安全问题不只是「模型说什么」，还有「谁能管这个模型」「数据怎么不裸奔」。

最后做成了一个 monorepo，包含三个子项目，全部零依赖（只用 node:crypto 和 node:http，Node 18+ 即可跑）：

SKG（信号-密钥围栏）

一个「非典型电子围栏」——围栏不是地理坐标，而是由签发密钥 + 环境信号指纹（WiFi BSSID / 基站 ID）来定义。评估端只学到「在不在围栏内」这一比特信息，原始设备 ID 用 RSA-OAEP 密封，只有签发方私钥能解封。

TriggerGuard（LLM 安全网关）

OpenAI 兼容的反向代理，输入侧做提示注入 / 越狱检测（20+ 条规则，含 leetspeak 和零宽字符混淆对抗），输出侧做后门触发和外泄检测，流式 SSE 能在中途截断。带哈希链审计日志。

SKG-Guard（合并 MVP）

把上面两个融合成一个可部署的网关。分工一句话：网关管内容安不安全，SKG 管谁能管网关、数据怎么不裸奔、密钥放哪。

合并版还做了几件事我觉得比较有意思：

  • 私钥外置：签发私钥不在网关进程里，单独跑一个签名服务（HSM 参考实现）。网关启动时只取公钥，authority.json 零私钥。
  • 设备端 SDK：零依赖单文件，浏览器 / Node 双端。宿主只需实现一个信号采集桥（一个方法：collectSignals() 返回 WiFi 和基站列表），SDK 负责上报包构造、防重放、请求注入。给了 Android / iOS / Node.js / Web 四个平台的最小示例。
  • Epoch 聚合：每次管理访问入池，seal=1 后打乱顺序只公布 granted/denied 聚合计数，切断时序关联。
  • Docker 部署：双容器（签名服务 + 网关），node:22-alpine 非 root，卷持久化。在 macOS arm64 / colima / Docker 29 上实测了完整冒烟流程。

测试方面写了 25 条安全性质断言（含外置签名服务端到端和设备 SDK 链路），全部通过。

文档方面也写得很详细——从威胁模型到诚实边界（MVP 的局限性）都列了清楚。比如我明确写了「围栏信号是演示级的」「签名服务是参考实现，私钥仍以 PEM 落盘」「浏览器拿不到 BSSID 必须由原生壳采集」。我觉得把这些局限性说清楚比藏着好。

三、CoreType — macOS 极简输入法

这个项目的起因很简单：我想做一个输入法，靠缩写展开 + 智能词库来实现「打字快到飞起」的体验。

用 Swift + IMK（InputMethodKit）框架，SwiftPM 管理工程。目前 MVP 还在开发中，但工程骨架已经搭好了：

核心引擎拆成了几个模块：

  • Abbreviation — 缩写展开引擎
  • Lexicon — 词库存储
  • Candidate — 候选生成与排序
  • Prediction — 上下文预测
  • Refinement — 文雅词替换（让输出不那么生硬）

关键设计决策是纯 Swift 核心引擎可独立测试（swift test 不需要 Xcode GUI），IMK 适配层只是个薄壳。各引擎之间用抽象协议解耦，方便后面换实现。还有一个 build_bundle.sh 脚本负责构建并组装 .app bundle 到 ~/Library/Input Methods/。

目标覆盖率 80%+。目前在 W2-W5 的功能阶段，预计 Q3 内出 MVP。

说实话，做输入法比我想象中复杂得多——光 IMK 的配置就踩了不少坑。但核心引擎的解耦设计我是满意的，后面换后端或者加功能都不会牵一发动全身。

四、本地工作台

这个不算什么大项目，但这个月花了不少时间在上面，算是给自己造的工具。

一个单文件 HTML 的本地工作台，用 Tailwind CSS 做了一套黑白灰的设计系统。功能包括：

  • 树状目录管理笔记和文件夹（右键菜单 + 拖拽排序）
  • Markdown 编辑器，支持实时渲染
  • 番茄钟（带进度环动画）
  • 待办管理
  • 快捷入口
  • 导出 PDF / Markdown / 纯文本
  • KaTeX 数学公式渲染、Mermaid 流程图、二维码生成和扫描
  • 深色 / 浅色主题切换
  • 本地 localStorage 自动保存
  • 数据导入导出

从 8 月 5 号做到 8 月 20 号，中间断断续续地打磨。说实话做完之后自己每天都在用——番茄钟和 Markdown 笔记这两个功能用得最频繁。单文件的好处是双击就能打开，不用装任何东西，换机器也不怕。

本月感想 & 下月展望

这个月最大的感受是：项目可以并行推进，但注意力不能。

四个方向同时跑，每个都有一股「再优化一点就好了」的冲动——nano 内核想压到亚纳秒、围栏想接真实 HSM、输入法想赶紧出可用版本、工作台想加更多功能。但人的精力是有限的，有些东西这个月只能做到「骨架完成，后续再说」的程度。

不过回头看，每个项目都有实质性的交付：研究原型跑通了完整验证流程、安全网关出了可部署的 MVP、输入法搭好了工程骨架、工作台已经在日常使用。算是没有空转。

下个月想做的事情：

  1. 研究原型这边，把 AI 评分接口接上，让 ProofOrchestrator 的 Move 选择真正由 LLM 驱动——现在还是纯规则的，离「AI 证明搜索」还差最后一步。
  2. 安全网关这边，想试试接真实的 HSM/KMS（比如 AWS KMS），看看签名接口能不能无缝替换。
  3. 输入法争取出第一个能用的版本——至少缩写展开和候选排序要跑通。
  4. 工作台想加一个看板视图，把待办和笔记串起来。

还有一些没想明白的事，比如 Lean 4 形式化骨架到底要不要在这个阶段投入精力——论文里的定理证明目前还是 sorry，要真正补完的话工作量不小。先看看 AI 评分接口接上之后的效果再说吧。

总之，八月没有虚度。九月继续。
